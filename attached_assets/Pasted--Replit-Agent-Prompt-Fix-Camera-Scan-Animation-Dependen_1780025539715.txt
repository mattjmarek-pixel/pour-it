## Section 1 — Fix Metro resolver for pnpm workspaces

**Problem:** `expo-camera` is installed but Metro cannot resolve it because pnpm uses symlinked `node_modules`. The camera silently falls back to fake random-product scanning.

**Steps:**

1. Open (or create) `artifacts/pour-it/metro.config.js` and replace its entire contents with:

```js
const { getDefaultConfig } = require('expo/metro-config');
const path = require('path');

const projectRoot = __dirname;
const workspaceRoot = path.resolve(projectRoot, '../..');

const config = getDefaultConfig(projectRoot);

config.watchFolders = [workspaceRoot];

config.resolver.nodeModulesPaths = [
  path.resolve(projectRoot, 'node_modules'),
  path.resolve(workspaceRoot, 'node_modules'),
];

config.resolver.disableHierarchicalLookup = false;

module.exports = config;
```

2. Open the root `.npmrc` file (create it if it doesn't exist) and ensure it contains:

```
shamefully-hoist=true
public-hoist-pattern[]=*expo*
public-hoist-pattern[]=*react-native*
public-hoist-pattern[]=*react*
```

3. Run `pnpm install` from the repo root to re-flatten the lockfile.

## Section 3 — Replace fake scan with real expo-camera barcode scanning

**Problem:** `ScanView.tsx` uses a fake tap-to-scan fallback that picks a random product.

**Steps:**

1. Open `artifacts/pour-it/components/ScanView.tsx`.

2. Remove all fake/simulated scan logic (random product selection and setTimeout fallback).

3. Replace the camera section with:

```tsx
import { CameraView, useCameraPermissions } from 'expo-camera';
import { useIsFocused } from '@react-navigation/native';
import { useRef } from 'react';

export function ScanView({ onProductScanned }: { onProductScanned: (barcode: string) => void }) {
  const [permission, requestPermission] = useCameraPermissions();
  const isFocused = useIsFocused();
  const scannedRef = useRef(false);

  function handleBarcode({ data }: { data: string }) {
    if (scannedRef.current) return;
    scannedRef.current = true;
    onProductScanned(data);
    setTimeout(() => { scannedRef.current = false; }, 3000);
  }

  if (!permission) return null;

  if (!permission.granted) {
    return (
      <View style={styles.permissionContainer}>
        <Text style={styles.permissionText}>Camera access is needed to scan bottles.</Text>
        <Pressable onPress={requestPermission} style={styles.permissionButton}>
          <Text style={styles.permissionButtonText}>Allow Camera</Text>
        </Pressable>
      </View>
    );
  }

  return (
    <CameraView
      style={StyleSheet.absoluteFillObject}
      facing="back"
      active={isFocused}
      barcodeScannerSettings={{
        barcodeTypes: ['ean13', 'upc_a', 'upc_e', 'qr'],
      }}
      onBarcodeScanned={handleBarcode}
    />
  );
}
```

4. Keep all existing viewfinder overlay UI — only replace the camera/scan logic.

5. In `ModeScreen.tsx`, update the barcode handler to look up the product in `src/data/recipes.ts`. If no match is found, show a "Product not found" message.

## Section 4 — Fix animations: useNativeDriver

**Problem:** All animations use `useNativeDriver: false`, which runs on the JS thread and freezes the camera when a scan fires.

**Rule:** Only `opacity` and `transform` (translate, scale, rotate) support `useNativeDriver: true`. Animations of `width`, `height`, or `backgroundColor` must remain `false` — refactor those to use transform equivalents.

**Steps:**

1. `ScanView.tsx` — switch scan-line animation to `transform: [{ translateY: scanAnim }]` and set `useNativeDriver: true`. Do the same for any pulse/opacity animations.

2. `ProductGrid.tsx` — change all fade-in opacity animations to `useNativeDriver: true`.

3. `RecipeList.tsx` — flip all opacity/transform animations to `useNativeDriver: true`.

4. `AIPanel.tsx` — the bottom-sheet uses `transform: translateY`, change to `useNativeDriver: true`.

5. Search the entire `artifacts/pour-it` directory for remaining `useNativeDriver: false` instances. Only leave `false` where the animation genuinely drives a layout property that cannot be refactored to transform.
