Your task is to migrate all Animated API calls from useNativeDriver: false to useNativeDriver: true across the mobile app. This is a performance fix — animations currently run on the JS thread, causing jank on real devices.

## BACKGROUND

useNativeDriver: true offloads animations to the native UI thread. It only supports transform and opacity properties. It does NOT support layout properties like width, height, top, left, padding, margin, backgroundColor, or borderWidth.

The migration strategy is:
- If an animation drives only transform/opacity → switch to useNativeDriver: true directly
- If an animation drives a layout property → refactor to use transform equivalents (translateX/translateY/scaleX/scaleY) to achieve the same visual result, then use useNativeDriver: true
- If a layout property cannot be replaced with transforms → keep useNativeDriver: false for that specific animation only, and add a comment: // layout property — native driver not supported

## COMMON PATTERNS TO WATCH FOR

Fade-in animations driving opacity:
  BEFORE: Animated.timing(fadeAnim, { toValue: 1, useNativeDriver: false })
  AFTER:  Animated.timing(fadeAnim, { toValue: 1, useNativeDriver: true })

Slide-up animations driving translateY:
  BEFORE: Animated.timing(slideAnim, { toValue: 0, useNativeDriver: false })
  AFTER:  Animated.timing(slideAnim, { toValue: 0, useNativeDriver: true })

Slide animations currently driving top/bottom/height (layout props):
  BEFORE: style={{ top: slideAnim }}
  AFTER:  style={{ transform: [{ translateY: slideAnim }] }}
  AND:    useNativeDriver: true

Scale animations:
  BEFORE: style={{ width: scaleAnim }}
  AFTER:  style={{ transform: [{ scaleX: scaleAnim }] }}
  AND:    useNativeDriver: true
